# 消防报警系统联动逻辑配置与调试审阅平台

面向消防工程师、调试人员和审阅人的联动逻辑工作台，支持设备台账、因果矩阵、互锁/延时/优先级配置、矩阵校验、依赖图、版本差异、联调清单和签字锁定。

## 技术栈

Vue 3 + Vuetify + Pinia + Vue Router + Apollo Client + GraphQL + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62048`。

```bash
npm run test    # 协同引擎 + 双标签页集成测试
npm run build   # 类型检查 + 构建
```

## 核心工作流

- 按楼层分区维护探测器、模块和消防设备，建立触发到动作的因果矩阵。
- 配置延时、互锁、优先级和抑制条件，并批量启停或修改矩阵规则。
- 自动发现遗漏、重复、自相矛盾和跨区冲突，在依赖图中定位问题。
- 比较专业提交版本并部分接受变更，完成联调清单后签字锁定交付包。

## 协同草稿模型（多标签页联调）

设备、因果规则和审阅批次都是可续作的协同草稿，两个标签页可同时编辑（`src/stores/collab.ts`）：

- **批次日志**：每次保存打包成带批次号（`窗口A#7`）的批次，追加到共享日志（localStorage），各窗口折叠同一份日志得到一致状态；批次携带因果向量 `seen`。
- **字段级合并**：不冲突的字段自动合到一起；同一规则同一字段被两个窗口同时改过时，两版都保留为待裁决冲突，审阅人在「版本审阅」页选择采用哪一版（或恢复原始值）后整版写回。
- **失败重试**：写入失败的批次留在本窗口的待写箱，按原批次号退避重试；批次号是幂等键，对端去重，日志中同一批次只出现一次。审阅页提供「模拟写入失败」开关演练该路径。
- **恢复闸门**：启动时回放日志并补写崩溃前遗留的批次，恢复完成（待写箱清空）前不能签字锁定、不能导出交付包。
- **旧稿升级**：首次启动把 v1 草稿整体迁移为一个迁移批次，为每条设备/规则补齐版本来源（来源标记、保留旧 revision、记录迁移批次号）。
- **结论失效重算**：接受变更时记录依据（关联规则及其触发/动作设备的版本）；审阅通过后这些设备或规则再被修改，对应结论即失效，需重新确认。
- **交付拦截**：未裁决冲突、失效结论、失效引用（规则指向不存在的设备）、未恢复完成，都会挡住签字锁定与交付包导出。
